# 個人 Blog 與內容管理設計

## 目標與範圍

此網站的首要目標是讓潛在雇主與合作夥伴快速理解作者作為廣泛技術領域軟體工程師的能力。公開網站以繁體中文呈現，提供 About、Projects 與 Blog；第一版後台僅供唯一管理者使用。

第一版包含：

- About 首頁、Projects 清單、文章列表與單篇文章頁。
- Markdown 文章的草稿、預覽、發布、編輯與刪除。
- About 內容及網站基本設定的管理。
- 主分類與多標籤的文章組織方式。

第一版不包含：多作者／角色、排程發布、專案的後台管理、媒體庫，以及站內專案詳情頁。

## 資訊架構

| 路徑           | 用途                                       | 存取權限   |
| -------------- | ------------------------------------------ | ---------- |
| `/`            | About 首頁，包含簡介、技能、經歷與社群連結 | 公開       |
| `/projects`    | 專案卡片清單，連往 GitHub 或 Demo          | 公開       |
| `/blog`        | 已發布文章列表，提供分類、標籤與分頁       | 公開       |
| `/blog/[slug]` | 單篇已發布文章                             | 公開       |
| `/login`       | 管理者登入                                 | 公開       |
| `/dashboard`   | 文章、About 及網站設定管理                 | 唯一管理者 |

固定導覽列保留 About、Projects、Blog。首頁不堆疊所有內容，以 About 為主，另以簡潔連結引導至作品與文章。

## 架構與資料流

沿用既有 Next.js 前端、Express API 與 Supabase。前端經由 Express API 讀取與更新內容；公開端點只會回傳已發布的文章。任何寫入請求都必須由 API 驗證唯一管理者的登入狀態。

Supabase `public` schema 的每張資料表均啟用 RLS。service-role 或其他私密金鑰只存在於伺服器端環境變數，絕不傳送到瀏覽器。前端不直接取得可寫入的資料庫權限。

文章流程為：管理者在 Dashboard 新建或編輯 Markdown 草稿，透過即時預覽確認，發布後才會出現在公開的文章列表和單篇頁；撤回發布後回到草稿並從公開端消失。

## 內容模型

### Supabase 資料

- `posts`：標題、slug、摘要、Markdown 內文、可選封面圖片網址、狀態、發布時間、SEO 描述及主分類。
- `categories`：文章主分類，例如 Frontend、Backend、DevOps。一篇文章只能指定一個分類。
- `tags`：技術或主題標籤，例如 React、TypeScript、Notes。一篇文章可有多個標籤。
- `post_tags`：文章與標籤的多對多關聯。
- `profile`：姓名、職稱、自我介紹、技能、經歷、社群連結及頭像等 About 資料。
- `site_settings`：網站名稱、首頁簡介與預設 SEO 標題、描述。

首次導入時，既有 About 的內容需移入 `profile`，避免首頁內容遺失。

### 本地專案設定

Projects 第一版採受 TypeScript 型別保護的本地設定檔，欄位為名稱、簡述、技術標籤、GitHub 連結、Demo 連結及可選圖片。這是刻意的範圍限制；日後若需要在 Dashboard 維護，才移入 Supabase。

## Dashboard

Dashboard 包含三個主要面板：

- **文章**：文章清單、依狀態或分類篩選、新增、編輯、二次確認刪除，以及 Markdown 編輯器與即時預覽。
- **About**：編輯個人簡介、技能、經歷、社群連結與頭像資料。
- **網站設定**：編輯網站名稱、首頁文字、預設 SEO 標題與描述。

文章編輯時須驗證必填內容、slug 唯一性及 Markdown 格式。圖片以 Markdown URL 插入，不提供上傳功能或媒體庫。

## 公開閱讀體驗

延續現有深色終端機與低對比玻璃面板語彙。文章列表支援主分類切換、標籤篩選與分頁；沒有符合文章時，顯示明確空狀態。文章頁安全地轉譯 Markdown，顯示分類、標籤、發布日期與上一篇／下一篇導覽。Projects 以精簡卡片呈現，外部連結採安全的另開視窗設定。

## 錯誤處理與安全性

- 未登入或非管理者存取 Dashboard 與管理 API 時，拒絕請求並導向登入或回傳一致的授權錯誤。
- 公開讀取永遠排除草稿；直接猜測草稿 slug 也不可取得內容。
- API 驗證輸入資料，並以一致的錯誤格式回傳；Dashboard 顯示清楚且可行動的錯誤訊息。
- 刪除文章前必須二次確認。
- Markdown 輸出必須經安全處理，避免 XSS。

## 驗證策略

- 後端測試：文章 CRUD、必填欄位與 slug 驗證、草稿不可公開、分類與標籤關聯、唯一管理者授權及錯誤回應。
- 前端驗證：公開 Blog 列表、單篇文章、分類／標籤篩選、登入保護與 Dashboard 核心流程。
- 上線前驗證 RLS 政策與公開／管理 API 的實際存取結果。
