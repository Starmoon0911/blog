# Blog 三版靜態設計規格

## 目標

在既有個人網站內完成三套可比較的 Blog 公開端設計。每套都包含文章列表與文章閱讀頁，共用同一批繁體中文硬編碼資料，讓評估聚焦在資訊架構與視覺層級。此階段不串接 API、Supabase 或後端，也不新增進場、捲動或頁面切換動畫。

## 共通體驗

- 延續現有深色終端機、等寬字與低對比玻璃表面的品牌語彙，沿用全站 Header、Footer 與影片背景。
- `/blog` 作為設計比較入口，預設顯示第一版；以可見的版本切換器切換三版，文章連結保留目前選擇的版本。
- `/blog/[slug]` 顯示對應版型的閱讀頁；不存在的 slug 使用 Next.js `notFound()`。
- 六篇硬編碼文章涵蓋 Frontend、Backend、DevOps 三個分類與多個標籤，並包含標題、摘要、日期、閱讀時間、內容章節及程式碼範例。
- 分類與標籤使用原生按鈕實際篩選；搜尋框與分頁只呈現設計狀態，不提供行為，並以文字清楚標示為預覽。

## 三種方向

1. **Editorial / 編輯精選**：大型精選文章、兩欄次要文章與寬鬆留白，強調策展、標題與閱讀節奏。文章頁採窄版正文與醒目的導言。
2. **Terminal Index / 終端索引**：以命令輸出、檔案索引和行號構成高密度列表，最貼近既有終端機識別。文章頁模擬 README／終端文件閱讀。
3. **Knowledge Archive / 知識檔案庫**：左側分類導航、中央文章清單與右側標籤摘要，強調可掃描性與知識管理。文章頁使用文件式目錄與 metadata 側欄。

三版只改變 Blog 內容區，不能改寫全站 Header、Footer 或既有首頁。版本切換器屬原型工具，選定最終方向後可整體移除。

## 響應式與可及性

- 從 375px 起可完整使用且不產生水平捲動；768px 與 1024px 逐步展開多欄布局。
- 文章正文桌面寬度限制在約 65–75 個字元，行高至少 1.7；手機正文至少 16px。
- 所有互動使用語意化連結、按鈕或輸入欄位；焦點樣式可見，主要點擊區至少 44px。
- 版本、分類與標籤的選取狀態同時以文字／邊框與 `aria-current` 或 `aria-pressed` 表達，不只靠顏色。
- Blog 新增內容不使用 Motion；既有全站動效不在本次範圍。

## 驗收

- 三版均可從列表進入同版型文章頁，再返回相同版本列表。
- 分類與標籤篩選能即時更新硬編碼文章，無結果時顯示清楚的空狀態與重設控制。
- 三版在手機、平板與桌面均保持層級清楚；鍵盤可操作所有切換與篩選控制。
- `bun --filter frontend test`（新增 Blog 資料／篩選測試）、`bun run lint` 與 `bun run build:frontend` 通過。
